## representing the Problem

Computing the score of a puzzle can be computationally expensive. To avoid a substantial drain on computing resources, so I opted to write fast code using bitwise operations. Looping through each character in a word of varying length would be computationally expensive due to the unpredictable branch conditions.

Each word and each set of letters can be represented by an “N-hot Vector”, where 1 at bit index i represents the presence of a letter in a subset of the alphabet. Center letters are represented by a One-Hot vector, so puzzles are composed of two vectors, and our dictionary is composed of M vectors.

Rather than represent these structures as arrays of boolean values, I realised that all information could be contained in a single 32-bit value. The approach looks like this:

1. Encode the given english dictionary of size N into a set of 32-bit integers
2. Represent a puzzle as two 32-bit unsigned integers.

3. To determine if a puzzle is valid for a given word, we perform an analogue of the operation:

        (~(key | ~local_word) == 1) && (center & local_word) 

    Where key is the set of letters, center is the one-hot center letter, and local_word is the set of letters in the word.

4. If the result is False, we know that there are no letters outside the given vocabulary.
